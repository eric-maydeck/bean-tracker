# UI rules

The design language in one place. Each rule says whether `checkLayout`
(`tests/ui/checkLayout.ts`, run by `npm run test:ui`) enforces it. UI feedback
from the user's manual phone checks becomes a new rule here, plus an assertion
when it can be automated.

| # | Rule | Enforced by `checkLayout`? |
|---|------|---|
| 1 | No sideways page scroll at any width (360–1280, and the user's phone in portrait 480×909 and landscape 1003×333). Wide tables scroll inside their own `.table-scroll`. | Yes |
| 2 | Buttons, badges and chips never wrap onto a second line. Exempt: picker buttons and Image Suggest candidate rows, whose titles and notes are content (badges inside them still never wrap). | Yes |
| 3 | No clipped or overflowing text in buttons, badges, chips or table cells. | Yes |
| 4 | Tap targets are at least 44×44 px on phones (≤480 px wide; CSS applies it ≤640). Exempt: column sort headers (`.sort-button` directly in a `th`): list view is dense by design, and compact is the phone view. | Yes (≤480; sort headers exempt) |
| 5 | Buttons sharing a row line up: same top, same height. | Yes |
| 6 | One place per action. An action lives in one spot, not duplicated across the page. | No (review) |
| 7 | Consistent wording: "Sign in" / "Sign out", the same verb for the same action everywhere. | No (review) |
| 8 | One icon set: Phosphor regular paths in `Icon.svelte` (fill only for the current tab); no emoji in navigation. | No (review) |
| 9 | Compact-view edit icons stay on one row; list-view edit actions are two fixed rows (save/cancel/delete over status actions). | Partly (rules 2 and 5) |
| 10 | Stats tiles are sized in `cqw` (container units), never fixed `rem`/`px` offsets. | Partly (rule 3 catches spill) |
| 11 | A viewport-conditional CSS override goes right after its base rule (equal specificity → source order wins). | No (review) |
| 12 | Every page/view state is in the URL (defaults omitted, case-insensitive, bad values ignored); inline edit state never is. | No (unit tests per parser) |
| 13 | Real-phone check (Firefox/Android, portrait and landscape) over the LAN dev server before pushing UI changes; `test:ui` passes first. | No (process) |
| 14 | Every group of options in a picker/select has a header, including a top/suggested group (user feedback 2026-10-04). | Yes for `role="option"` pickers (checkLayout rule 7); native selects: review |
| 15 | Chips and badges use short forms where a well-known one exists (e.g. BQ for Bean Conqueror); the full name stays in editors/forms (user feedback 2026-10-04). | No (review) |
| 16 | Bag text ("1.5kg (1.2kg left)") never wraps onto a second line, in any view (user requirement 2026-10-04). | Yes |
| 17 | A row of buttons on a phone never leaves one button orphaned on its own line at a different width: the buttons share the row evenly (grow to fill each line, no doubled gaps). Mark the row `data-button-row` (user feedback 2026-10-05). | Yes for `[data-button-row]` at ≤640 px (checkLayout rule 8) |
| 18 | Images are never cropped: show the whole image (`object-fit: contain`) on a fill color computed from it (`coffeeImage().fill`, neutral `#e6ddd2` until computed) (user feedback 2026-10-05). | Yes (checkLayout rule 9: any image whose box shape differs from its own) |
| 19 | An inline edit form always shows its Save and Cancel/Discard under the form, reachable in the viewport from where the user is editing; never only above it or missing (user feedback 2026-10-05). | Per state: `expectActionsUnderForm` (`layout.spec.ts`, `coffees-*-inline-edit-actions`) |
| 20 | An inline edit's action row (Save/Cancel/Delete/status icons) under the form stays on one line at phone width whenever its buttons fit, and looks the same in Cards, List and Compact (user feedback 2026-10-05). | Per state: `expectActionsUnderForm` |
| 21 | An inline edit's action buttons are all within the viewport at phone width, and inside their own card or row at every width (they wrap rather than spill into the next card), in every view (List's wide table must not push them off-screen) (user feedback 2026-10-05). | Per state: `expectActionRow` (`coffees-*-inline-edit-action-row`) |
| 22 | The spacing above and below an inline edit's action row is the same in every view (about 16 px above, 12-18 px below) (user feedback 2026-10-05). | Per state: `expectActionRow` |
| 23 | An inline edit's action row starts at the form's left edge, lined up with the form's own buttons (Clone, Edit), in every view (user feedback 2026-10-06). | Per state: `expectActionsUnderForm` |
| 24 | Buttons come in three tiers: solid primary (`.button`, one per area; `.button-solid` for a solid one in a variant's hue, e.g. green Save), tonal secondary (`.button-secondary`/`-danger`/`-success`: tint fill, same-hue text), and ghost (`.button-ghost`, text only) for navigation, cancel and discard. Hover and keyboard focus invert the fill (hover only where the device can hover); disabled buttons dim and don't react; no state changes the button's size. Text is at least 4.5:1 against its fill in both themes, at rest and on hover. View toggles keep their own look with a gentle accent-tint hover (user decision 2026-10-08). | No (review) |
| 25 | Every tab or panel carries a purposeful, substantial amount of content; sibling views stay balanced (no 15 tiles in one and 2 in the other) (user decision 2026-10-10). | No (review) |
| 26 | A tile affected by a mode switch (e.g. Current/All ratings) carries that switch itself; every copy drives the same URL param, so all copies stay in sync (user feedback 2026-10-10). Exception: the people switch (Household / Per person) is one switch in the sticky filter bar, always in view (stats-per-person spec). | No (review; `insights-ratings-switch-sync` state checks the insights copies) |
| 27 | Mode switches and mode labels get a concise tooltip that works on hover, touch and keyboard: a `title` + `aria-describedby` on the switch options, and the label's mode word as a small button opening a native `popover` (user feedback 2026-10-10). | No (review; `insights-ratings-tip` state checks the insights one) |
| 28 | Panels don't leave visible empty space (e.g. a lone tile in a 4-column row); flag it in reviews and fill it as tiles and charts arrive (user feedback 2026-10-10). | Insights: `expectStatRowsFull` on every insights state; elsewhere review |
| 29 | A change/trend figure: metrics with a good direction (polarity) color by good/bad (green good, red bad; `--color-fresh` / `--color-urgent`); metrics with no good direction color by direction (up green, down red); no change stays gray (user feedback 2026-10-10). Diverging deltas (lab heatmaps, same-bag bars, the mineral map's vs usual) are green = better, neutral gray = about 0, red = worse, on one FIXED absolute scale (`deltaColor.ts`), the same code for every diverging mark (heatmaps, bars, the rest heatmap, Water ×, Gear, the mineral map): |Δ| < 0.05 is plain gray; any |Δ| ≥ 0.05 starts at a clearly visible tint floor (`--div-floor` per theme, 35% light / 52% dark: the first tint is ≥ 10 OKLab ΔE×100 from the gray, checked by `divFloor.test.ts`) and ramps linearly to full color at 0.4 rating points; never scaled to a chart's own max, so a color means the same size of difference everywhere (user, 2026-10-12; floor added 2026-10-13: small deltas read too gray) (`--div-high` / `--div-mid` / `--div-low`: a teal-green and a red-orange that stay apart under red-green color blindness; the signed number in the tip is the second channel). A measure with no better side (grind drift) uses one neutral ink (`--color-text-muted`), never green/red or hot/cold; the side of zero shows the direction (user feedback 2026-10-12). Thin data (few brews) on a delta color is a separate cue that never washes the hue out: surface stripes over the full tint (`--thin-hatch`), never opacity; neutral marks (mineral amounts) may still fade to `--faded`. A signed rating delta shown as text ("+0.12 vs same bag": boards, Ratings by recipe, the mineral map's vs usual, pair headlines, Sweet spots evidence, tips) is green (`--div-high-ink`) from +0.05, red (`--div-low-ink`) from −0.05, default ink between, with its sign, on the same thresholds as the scale (`deltaInk`), on thin (few brews) rows too, whose other numbers stay muted (user, 2026-10-13). A secondary line under a figure (e.g. the pace) is its own smaller gray line, never inlined into the figure's line (user feedback 2026-10-10). | Partly (`insights-compare-longer`: pace line clear of delta and caption; color class per tile; `expectDeltaInk` on Sweet spots, Brewing, Water, Gear: every delta text's color; `insights-brewing`: every bar and heat cell's computed color matches the scale, thin marks striped at opacity 1) |
| 30 | Stats filter bars (/insights controls, /stats tabs + people switch) stay pinned to the top while scrolling, on a solid background, above tiles and below dialogs; in phone landscape they are one short row. A scrolled-to panel starts below the bar (user decision 2026-10-10). | Per state: `expectStickyBar` (`insights-sticky`, `stats-sticky`, `stats-bq-sticky`) |
| 31 | Leaderboards show top 10 for many-item dimensions and top 5 for small sets; cards in a band are the same height, with faint placeholder slots where no following card can fill the space (rule 40) (user decision 2026-10-10). | Per state: `expectEqualBoardHeights` (`insights-leaderboards*`) |
| 32 | Option controls: a segmented switch for 2–4 short options that fit one row at 360px (Current \| All, Household \| Per person); a native dropdown for 5+ options, long labels, or grouped options (optgroups, rule 14), e.g. Rank by and Score (user decision 2026-10-11). Sibling controls in one bar share a baseline. | Alignment per state: `insights-leaderboards-avg` |
| 33 | Card grids (records, milestones, insights, Sweet spots, any lab card grid) always fill their rows at every width: the column count divides the items or the last row's cards widen; a lone or stray card is a defect (user, 2026-10-11). On phones (the grid under 520px) a row holds at most 2 cards, so each shows more than its title; an odd count ends in one card spanning the full row (at the end of each Findings size class too) (user, 2026-10-13). A strip of single-figure totals (`.stat-strip`, Milestones' summary) is a stat row (rule 28), not a card grid. | Yes (`expectGridRowsFull`: `insights-records`, `insights-milestones`, `insights-insights`, `insights-sweetspots`; phone rows ≤ 2, odd last spans) |
| 34 | Insights Findings cards have bounded sizes, chosen by rule, not curation (user, 2026-10-12). A card with a chart (`series`, `multi`, bars) or a versus split is LARGE-content; any other is SMALL-content. Each class packs into its own full rows (`sizedGrid`, strength order kept; the strongest card's class first; a class of one card makes every card LARGE). A row's height is a token: rows of 4/5 SMALL 160 / LARGE 264 px, any row of 3 252 px, 2-up rows (and a phone's lone full-width last card) SMALL 192 / LARGE 296 px. Content is forced to fit: charts take the spare height (min 24 px), details fill only true spare (B7), headline and body clamp to 3 lines, then step down (`data-tight` 1–3) until they fit; clamped text shows on hover (title) and on tap (popover). A card that still overflows is a defect. | Yes (`insights-insights`: equal heights = token ±2 px, rows one class, no overflow, at all 7 widths) |
| 35 | Lab charts: same-bag deltas are zero-centered bars (positive right, green/red by polarity), striped under 3 bags or 30 brews (the tip says "few brews"); thin data shows striped, never hidden; heatmaps use the diverging scale and scroll inside themselves on phones with the row labels pinned; the page never scrolls sideways (user spec 2026-10-12). A chart of an ordered dial (grind) spans every band brewed in its data, lowest to highest, no-match bands included (Sweet spots draws a dotted mark at 0), nothing outside that range; Sweet spots' Grind card and Brewing's Grind chart show the same bands (user, 2026-10-13). | Yes (`expectInnerScroll`: `insights-brewing-by-*`, `insights-water`, `insights-gear`; pale rows: `insights-brewing-zp6`; grind bands: `insights-sweetspots` vs Brewing) |
| 36 | One tip look, everywhere (lab and every Insights tab; hover, tap and keyboard tips, chart tips, help `?` popovers, canvas chart tooltips): `TipBody.svelte` content in one frame (`.cell-tip` / `.mode-tip` share padding, type, border, radius; Chart.js draws no tooltip of its own: its tooltip model renders as TipBody in a FloatTip, the x label as the title and each series as a label/value row). A bold title first; then data tips: 1–4 label/value rows (label muted, value right-aligned, ~240px max); help popovers: at most 6 lines, one idea per line (≤ 120 characters), a term and its explanation on its own line, a pair that describes the same thing kept on one line with ` · ` ("Green: better than usual · red: worse"). No paragraphs, no loose text, never "A: x. B: y." on one line; never what the chart already shows at that spot. SD, wherever it shows (board columns, tips), opens "SD · standard deviation": "How much ratings vary from brew to brew." / "Small: consistent · big: hit or miss." A share tip (usage over time) puts the series and its share in one row ("V60  38%", no "Share" label) under the month; an "Other" tip lists its members, up to 8 from 768px and 4 on phones, then "+N more" (a single leftover is shown instead of "+1 more"). Habits heatmap and calendar tips are data tips too ("Brews (avg)  0.31"; `expectDataTip`). Exempt: list tips (Records ties: one entry per row, name then muted date) and a clamped line's full-text tip (title only) (user feedback 2026-10-12, 2026-10-13). | Yes (`insights-consumption-compare-tooltip`: a canvas chart's tip is the shared tip, rows without "Label:"; `expectTipsFormatted` on every `insights-*` state: every help popover has its title first, rows or lines, no loose text, short single-idea lines; lab states check a chart tip's title + rows) |
| 37 | Paired lab columns (two charts side by side, or a card beside a stack of cards, rule 40) are one height H = clamp(shorter natural, taller natural, max(shorter natural + its stretchable body, 20rem)) (`fitPairs.ts`, one helper for every pair): rows grow at most 2× (headings and padding don't grow; a stack grows each card's body by one ratio), and a column past H scrolls inside (a stack: its tallest card). The shorter card's rows stretch to fill H (marks keep their thickness; rows just get taller); a taller card past H scrolls inside its own `.fit-body`. No empty space inside either card, and no fixed row cap with centering (user decision 2026-10-12). A stretched chart scales up, not apart: fitPairs sets `--grow` on the `.fit-body`, bars thicken toward ~60% of the row (at most 32px) and labels grow up to 1.2× (user, 2026-10-12). | Yes (`expectPairsFilled`: `insights-brewing*`, `insights-water`) |
| 38 | User-visible text uses American English spelling (color, center, favorite, behavior, analyze, canceled, labeled, gray), in the UI and in code comments and docs; stored data values and Bean Conqueror field names keep their original spelling (user request 2026-10-12). | No |
| 39 | Chart tips (hover, tap, keyboard) are never clipped: they render in the top layer (`FloatTip.svelte`, a manual popover) placed from the anchor's rect (`floatTip.ts`): above the anchor, below when there's no room under the sticky filter bar, clamped 8px inside the viewport, re-placed on scroll and resize. No card overflow, scroll wrapper, sticky bar or viewport edge cuts one (user, 2026-10-12). | Per state: `expectTipInView` (`insights-brewing*`, `insights-water`) |
| 40 | Leftover column space holds real content, not filler. When two cards share a row and one is much shorter, the next compact card stacks under the shorter one in that column (e.g. Gear: Filters within each dripper under the board with fewer rows, beside the longer board), and the two columns follow rule 37 exactly (one height, rows ≤ 2×, the over-cap column scrolling inside). A list of blocks of varying height (Same bag, different water) flows in balanced columns (CSS `columns`, `break-inside: avoid`; one column on phones); an expanded block, and the odd last of a run, spans both columns, so the columns end within one row of each other. Placeholder rows (rule 31) remain only where no following card can fill the space (user, 2026-10-13). | Yes (`expectColumnsFilled`: `insights-gear` ≥ 768 px on seed data and with injected rows (a far longer board, a far taller stack): columns one height, rows ≤ 2× (or the 20rem floor), no placeholder beside a stacked card, no empty space in a card; `insights-water`: pair columns end within one bag row, collapsed and expanded) |
| 41 | Targets and color hug their content. A text label's tip opens from the text itself (hover, tap, focus), never from the empty part of its cell (on phones the target still grows to 44×44, rule 4). A colored value in a table is a chip sized to its value with modest padding, in a column that hugs it (a missing value is a chip-sized muted dash, so it never widens the column), so color never spans empty space; on a filled chip the fill carries the delta color (T3 scale) and the text stays ink for 4.5:1 (user, 2026-10-13). | Yes (`insights-water`: the mineral map's name target sits inside its cell, a click on the cell's empty space opens no tip, every row's vs usual cell is at most 24px wider than its content) |
| 42 | Categorical colors (recipes, gear, line series: `--series-1..10`) are clearly distinct in light and dark: slots 1–5 every two ≥ 18 apart in OKLab (×100), all 10 every two ≥ 14, each ≥ 12 from the muted Other (pink beside red is a fail). A page that names things by color keeps one color per name everywhere on it (`nameColors`: Water's usage bars, pair headers, every swatch; usage lines first, then the rest); "Other" stays a gray segment while its members keep their own colors elsewhere; two names share a color only once the 10 slots run out, and then never two shown together (one bar, one pair). A comparison list of groups (Same bag, different water) gives each group its own bordered block with a gap between, column headers naming the compared items in their colors (a color block + name), plain values in the rows, and the winner's value bold and green; no colored underlines (user, 2026-10-13). | Yes (`palette.test.ts` ΔE per theme; `nameColors` unit tests; `insights-water`: one color per recipe and one recipe per color across legend and pair headers, two distinct header swatches per pair, plain scores, winners bold + green only, bordered blocks, rows full) |

Opting out: put `data-layout-ignore="<why, and the backlog item that tracks it>"`
on the element. An empty reason fails the check.
