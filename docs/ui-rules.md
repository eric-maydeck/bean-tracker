# UI rules

The design language in one place. Each rule says whether `checkLayout`
(`tests/ui/checkLayout.ts`, run by `npm run test:ui`) enforces it. UI feedback
from the user's manual phone checks becomes a new rule here, plus an assertion
when it can be automated.

| # | Rule | Enforced by `checkLayout`? |
|---|------|---|
| 1 | No sideways page scroll at any width (360–1280, and the user's phone in portrait 480×909 and landscape 1003×333). Wide tables scroll inside their own `.table-scroll`. | Yes |
| 2 | Buttons, badges and chips never wrap onto a second line. Exempt: picker buttons and Image Suggest candidate rows, whose titles and notes are content (badges inside them still never wrap). | Yes |
| 3 | No clipped or overflowing text in buttons, badges, chips or table cells. | Yes |
| 4 | Tap targets are at least 44×44 px on phones (≤480 px wide; CSS applies it ≤640). Exempt: column sort headers (`.sort-button` directly in a `th`): list view is dense by design, and compact is the phone view. | Yes (≤480; sort headers exempt) |
| 5 | Buttons sharing a row line up: same top, same height. | Yes |
| 6 | One place per action. An action lives in one spot, not duplicated across the page. | No (review) |
| 7 | Consistent wording: "Sign in" / "Sign out", the same verb for the same action everywhere. | No (review) |
| 8 | One icon set: Phosphor regular paths in `Icon.svelte` (fill only for the current tab); no emoji in navigation. | No (review) |
| 9 | Compact-view edit icons stay on one row; list-view edit actions are two fixed rows (save/cancel/delete over status actions). | Partly (rules 2 and 5) |
| 10 | Stats tiles are sized in `cqw` (container units), never fixed `rem`/`px` offsets. | Partly (rule 3 catches spill) |
| 11 | A viewport-conditional CSS override goes right after its base rule (equal specificity → source order wins). | No (review) |
| 12 | Every page/view state is in the URL (defaults omitted, case-insensitive, bad values ignored); inline edit state never is. | No (unit tests per parser) |
| 13 | Real-phone check (Firefox/Android, portrait and landscape) over the LAN dev server before pushing UI changes; `test:ui` passes first. | No (process) |

| 21 | An inline edit's action buttons are all within the viewport at phone width, and inside their own card or row at every width (they wrap rather than spill into the next card), in every view (List's wide table must not push them off-screen) (user feedback 2026-10-05). | Per state: `expectActionRow` (`coffees-*-inline-edit-action-row`) |

| 24 | Buttons come in three tiers: solid primary (`.button`, one per area; `.button-solid` for a solid one in a variant's hue, e.g. green Save), tonal secondary (`.button-secondary`/`-danger`/`-success`: tint fill, same-hue text), and ghost (`.button-ghost`, text only) for navigation, cancel and discard. | 29 | A change/trend figure: metrics with a good direction (polarity) color by good/bad (green good, red bad; `--color-fresh` / `--color-urgent`); metrics with no good direction color by direction (up green, down red); no change stays gray (user feedback 2026-10-10). Diverging deltas (lab heatmaps, same-bag bars, the mineral map's vs usual) are green = better, neutral gray = about 0, red = worse, on one FIXED absolute scale (`deltaColor.ts`), the same code for every diverging mark (heatmaps, bars, the rest heatmap, Water ×, Gear, the mineral map): |Δ| < 0.05 is plain gray; any |Δ| ≥ 0.05 starts at a clearly visible tint floor (`--div-floor` per theme, 35% light / 52% dark: the first tint is ≥ 10 OKLab ΔE×100 from the gray, checked by `divFloor.test.ts`) and ramps linearly to full color at 0.4 rating points; never scaled to a chart's own max, so a color means the same size of difference everywhere (user, 2026-10-12; floor added 2026-10-13: small deltas read too gray) (`--div-high` / `--div-mid` / `--div-low`: a teal-green and a red-orange that stay apart under red-green color blindness; the signed number in the tip is the second channel). A measure with no better side (grind drift) uses one neutral ink (`--color-text-muted`), never green/red or hot/cold; the side of zero shows the direction (user feedback 2026-10-12). A small sample (`src/lib/sample.ts`: pooled under 3 bags or 10 brews, one bag under 4 brews) is one cue everywhere: text muted (`.small-sample`, never opacity), a colored mark striped over its full tint plus an amber corner fold, top left (`.small-sample-mark`: `--thin-hatch` and `--chip`), and on text rows a solid amber "Low confidence" chip with the Phosphor warning icon, dark ink (`SampleNote`, `.sample-chip`, `--chip` / `--chip-ink`); the chip never repeats a count. Every marked thing has a tip: the reason line ("Small sample: only 2 bags, so one bag can swing this. Needs 3+ bags and 10+ rated brews.") and the exact counts, from `sampleTip` / `sampleBody` in `sample.ts` (wording fallback if "Low confidence" ever crowds a row: "Small sample" everywhere, then "Only 2 bags"); a help popover's legend line (`SAMPLE_HELP`) shows the chip and a striped swatch (user, 2026-10-15). The fold is always at the TOP LEFT, on horizontal and vertical bars, canvas bars, heat cells and chips (a clipped bar's fold moves just past its arrow taper). A same-bag comparison's tip counts "Bags brewed both ways" and "Rated brews in them"; only one tip is open app-wide (`FloatTip` dismisses the previous one), and a mineral map row's name and chip are one target; a Water pair ("Same bag, different water") gets ONE chip under its heading when over half its bags have a side under 4 rated brews; its tip says how many. The strength badges read "Likely" (gap at least 2x normal brew-to-brew noise) and "Possible" (1.5 to 2x); no badge under 1.5x; pills, never amber. Neutral marks (mineral amounts) may still fade to `--faded`. A signed rating delta shown as text ("+0.12 vs same bag": boards, Ratings by recipe, the mineral map's vs usual, pair headlines, Sweet spots evidence, tips) is green (`--div-high-ink`) from +0.05, red (`--div-low-ink`) from −0.05, default ink between, with its sign, on the same thresholds as the scale (`deltaInk`), on thin (few brews) rows too, whose other numbers stay muted (user, 2026-10-13). A secondary line under a figure (e.g. the pace) is its own smaller gray line, never inlined into the figure's line (user feedback 2026-10-10). | Partly (`insights-compare-longer`: pace line clear of delta and caption; color class per tile; `expectDeltaInk` on Sweet spots, Brewing, Water, Gear: every delta text's color; `insights-brewing`: every bar and heat cell's computed color matches the scale, small marks striped at opacity 1: `insights-sample-marks`, `insights-sample-note`) |
